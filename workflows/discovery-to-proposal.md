# Workflow: discovery call to proposal

**Lead:** solutions-architect · **Playbooks:** `playbooks/discovery-call.md`, `playbooks/proposal.md` · **Ends with:** a proposal and price in the approval queue

| # | Step | Who | Reviewer | Output |
|---|---|---|---|---|
| 1 | Brief before the call | solutions-architect with `sales-discovery-coach` | | `clients/<slug>/discovery/brief.md` |
| 2 | Demo plan | `sales-engineer` | | 5-minute demo outline |
| 3 | Founder runs the call | founder | | Notes or transcript |
| 4 | Requirements | solutions-architect | `sales-deal-strategist`: risks, who decides, fit | `requirements.md` |
| 5 | Solution design | solutions-architect with the right builder's specialists (`engineering-software-architect`, `automation-governance-architect`, `design-ux-architect`) | | Design section |
| 6 | Price | solutions-architect with `specialized-pricing-analyst` | | Price and assumptions |
| 7 | Proposal | `sales-proposal-strategist` | `testing-reality-checker`: no promise we can't keep | Proposal draft |
| 8 | Approval queue, type `price` | solutions-architect | | Queue item |
